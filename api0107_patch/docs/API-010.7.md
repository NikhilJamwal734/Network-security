# API-010.7 — Bounded Service-Group and IPv6 Selector Review

## Purpose and compatibility

API-010.7 is **additive**. It invokes API-010.6's `analyze_object_assurance`, preserves the entire previous JSON response verbatim at the top level, and adds only `service_ipv6`. It does **not** modify normalized security findings, severity counts, provisional review scores, or rule-correlation observations.

The endpoint is `POST /api/v1/analyze/service-ipv6`, with multipart `file` and optional `platform`. The endpoint reads a capped source snapshot **before** API-010.6 closes its upload, avoiding the previously encountered `ValueError: I/O operation on closed file`.

## Supported static subset

| Platform | Supported | Not established |
|---|---|---|
| Cisco ASA | Single IPv6 `host` or `/prefix` network objects; extended TCP/UDP ACLs with `any6`, `host`, named object, literal IPv6 prefix and numeric destination port; comparison within same named ACL | IPv4 ACL expansion (handled elsewhere), ASA object/service groups, source port, service aliases, `log` modifiers, interfaces, effective ACL ordering and NAT |
| FortiOS | Explicit `config firewall address/addrgrp`, `address6/addrgrp6`, `service custom/group`, `policy/policy6`, nested address or service groups; numeric TCP/UDP destination port ranges and same interface/schedule selectors | Built-in service definitions absent from the upload, VDOMs, custom source ports, FQDN, dynamic/exclusion selectors, negation, NAT, zones, policy insertion/position and effective reachability |
| Snort | Existing analysis preserved | IDS variable expansion is not assessed by this module |
| Suricata | Existing analysis preserved | IDS variable/include expansion is not assessed by this module |

Network and service dependencies are resolved with caps on depth, size, definitions, and result count. Cycles, duplicate definitions and unknown mutations are not guessed.

## Output model

`service_ipv6` contains:

- `status`: `reviewed_subset`, `limited`, or `not_assessed`.
- `summary`: definitions seen/resolved/unresolved, rules seen/eligible/not assessed, candidates and omissions, incomplete processing flag.
- `objects`: bounded evidence inventory with source line and explicit status/reason.
- `pairs`: bounded candidate correlations, paired rule lines/IDs, related objects, confidence, ordering status, recommendation, explanation.
- `limitations`: statements of excluded semantics and processing limits.

A candidate only means supported traffic selectors intersect; it is **not** proof of effective policy conflict or exploitable access.

## Frontend and PDF separation

The Dashboard renders compact snippets, not detailed object listings: four metrics, at most two candidate previews for API-010.7, and one preview for the earlier object resolution/reference panels. The earlier four review sections stay as already compacted; sidebar, PDF theme, and other Dashboard sections are untouched.

The formal PDF contains all `service_ipv6.objects` returned by the server (up to 120), all `service_ipv6.pairs` (up to 40), source lines, supporting object references, candidate rationale, recommendations, score/coverage interpretation, and limitations. If the backend omits objects/pairs due to limits, the PDF discloses incompleteness. The existing API-010.0 through 010.6 PDF sections remain in place.

## Threat model and constraints

- Static upload analysis only; no device access, code execution, or fetching referenced files.
- Source snapshot capped at 2 MiB, lines at 40,000, definitions at 400, resolved rules at 100, candidate pairs at 40, group recursion at 10.
- Unrecognized syntax is excluded; this may lead to false negatives, explicitly covered by scope limitations.
- Requires the complete relevant device configuration for meaningful dependency comparisons.
- No persistent storage or new frontend JSON downloads.
