# API-011.0 — Cross-review evidence consolidation

## Design intent

**Scope:** add a common, bounded, advisory provenance and quality check over
previous review responses **for one uploaded configuration**. The supported
normalized platform IDs are `cisco_asa`, `fortios`, `snort`, and `suricata`.
The stage cannot validate a cross-device path or claim detection is active.

**Endpoint:** `POST /api/v1/analyze/consolidated`, multipart file plus optional
`platform`. This invokes 010.9's analyzer unchanged, then adds
`consolidation_review` to the response. The upload is never read a second time,
so it remains safe when the 010.9 processing chain closes UploadFile.

## Evidence review

- Records whether the normalized findings, object-resolution, object-assurance,
  service/IPv6, NAT/routing and IDS deep-review sections were returned.
- Distinguishes absent sections from returned sections that explicitly mark
  analysis limited or not assessed. Absence never means no security issues.
- Checks reviewer platform metadata and `evidence_items` count consistency.
- Flags **candidate links only when the same positive source line, exact
  signal identifier AND exact title** occur in **different review sections**.
  Links are explicitly not confirmed duplicates. No finding is removed.
- Cap: 400 inspected items per section, 1,500 total, 36 quality observations,
  and 24 candidate links. Truncation is reported. Reference and text sizes are
  bounded. The upstream analyzer's own limits still apply.
- Full original findings, ranking, severity counts, and risk score are returned
  without alteration. No recommendation is automatically applied.

## Dashboard vs PDF

**Dashboard:** new compact card with section count, inspected items, candidate
links, metadata observations, and up to two short issue kind-label snippets.
No long-form explanation, technical evidence, source snippets or remediation.
Other cards and navigation remain untouched.

**PDF:** inventory of section coverage and explicit omissions, full quality
observations with confidence and recommendations, candidate links including
source line and related identifiers, and limitations. Previous PDF sections
are preserved. All labels are bounded text from static normalized fields.

## Caveats

This release does not merge different uploaded configurations into a single
estate model. Source-line similarity is treated conservatively. A zero-candidate
result is not evidence that no conflicting policies or duplicate findings exist.
Missing/unsupported outputs are recorded as limited coverage. This is a
report-level quality-control layer, not a new traffic simulation engine.

## Validation

The package includes unit tests, installer preflight and idempotence tests,
synthetic endpoint tests including upstream UploadFile closure, frontend
snippet/PDF boundary tests, and rollback functionality. Always run your full
project test suite and TypeScript production build on your machine.
