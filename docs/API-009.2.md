# API-009.2 — Conservative Platform Detection & Safe Routing

## Scope

The existing `POST /api/v1/analyze` remains unchanged for Cisco ASA clients.

New `POST /api/v1/analyze/universal` accepts a multipart field called `file` with extensions `.conf`, `.cfg`, `.txt` and optional query parameter `platform=cisco_asa`. The route uses `app.security.untrusted_config.read_untrusted_config` for the same input validation as the existing endpoint. Only registered, implemented platform adapters execute.

The auto-detector recognizes **strong Cisco ASA commands** (`object network`, ASA `access-list ... extended`, `nameif`, `security-level`, etc.). Generic `hostname` or `interface` alone are not enough to auto-detect Cisco ASA. For such minimal configurations, the caller can pass `platform=cisco_asa`; an explicit choice must still contain at least one recognizable ASA-style command and no conflicting IDS syntax.

The detector *does not* claim Snort or Suricata support. Snort/Suricata-like signatures and Suricata YAML markers are blockers, because those platform grammars overlap and neither analyzer has been implemented. Mixed ASA and IDS markers produce `422 ambiguous_configuration`.

## Endpoints

- **GET /api/v1/platforms**: returns only registered and verified platforms, currently Cisco ASA.

- **200**: recognized, supported Cisco ASA config. Existing report fields plus `platform_detection: { platform_id: "cisco_asa", method: "automatic" | "explicit" }`.
- **400**: unsupported extension or unsupported explicitly requested platform.
- **413**: upload/line size exceeds the existing validator limits.
- **422**: unknown, ambiguous, unsupported file syntax, or declared-platform content mismatch. A missing upload also returns FastAPI's validation 422.

## Install

Extract the ZIP to the project root. Add **one import** and **one include_router** call to `app/api/main.py` as described in the accompanying assistant response. Do not replace existing backend modules.

```python

# After `app = FastAPI(...)` (and CORS setup):
app.include_router(universal_router)
```

## Security and limitations

- The uploaded text is untrusted data, never executable code.
- The registry is explicitly curated; uploaded content cannot register a parser.
- The detector inspects only anchored command shapes, ignores standalone comments, and never dynamically imports code.
- Explicit platform selection is a hint subject to validation, not an instruction to execute arbitrary text.
- Detection is heuristic. Mixed, partial, unfamiliar, and unsupported configurations may require manual review or later dedicated parsers.
- Static configuration analysis is not proof of real-world network security.
