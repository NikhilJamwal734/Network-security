# API-009.3 — Normalized Security Models

## Purpose

Expose a **new**, opt-in JSON report structure for firewall / IDS / IPS platforms while preserving the legacy Cisco ASA API results. Existing adapters are not changed, and files remain **untrusted data**.

### Files

- `app/core/normalized_models.py` — immutable models, severity and coverage enums, JSON serialization.
- `app/core/normalization.py` — explicit Cisco ASA report converter (no guessing about other vendors).
- `app/api/normalized.py` — `POST /api/v1/analyze/normalized`, reusing API-009.2 upload validation and routing.
- `app/api/main.py` — existing file with one extra import and router registration.
- `tests/test_api_009_3_normalized.py` — new schema and compatibility tests.

### Endpoint

`POST /api/v1/analyze/normalized` (multipart field `file`, optional query parameter `platform=cisco_asa`).

It does **not** replace `/api/v1/analyze` or `/api/v1/analyze/universal`.

```json
{
  "schema_version": "1.0",
  "platform": {
    "platform_id": "cisco_asa", "display_name": "Cisco ASA", "family": "firewall",
    "hostname": "ASA-FIREWALL", "detection_method": "automatic"
  },
  "summary": {
    "total_findings": 29,
    "severity_counts": {"critical": 1, "high": 4, "medium": 3, "low": 21, "info": 0, "unknown": 0},
    "security_score": 21, "risk_level": "CRITICAL"
  },
  "findings": [],
  "coverage": {"assessment_type": "static_configuration", "domains": [], "limitations": []},
  "warnings": []
}
```

The empty findings/domains arrays in the abbreviated example are placeholders, not the actual response for 29 findings.

### Important scope boundaries

- Only Cisco ASA is normalized at this milestone; Snort and Suricata still need dedicated adapters and mappings.
- The security score is the **unchanged Cisco ASA score**, not a cross-platform score.
- A coverage domain marked `assessed` means the existing ASA analyzer runs related static checks; it **does not** establish comprehensive coverage or runtime detection effectiveness.
- `finding_id` is unique within a report, not necessarily stable across changed configurations.
- Findings descriptions, titles, and recommendations are untrusted **text fields** and must be rendered in React as text, never interpreted as HTML or commands.
- Raw configuration lines and arbitrary platform data are **not copied** into the normalized report. Original reports remain available via the existing endpoints.

### Install

From the project root, extract this ZIP, preserving the directory structure. Back up `app/api/main.py` if it differs from your known-good API-009.2 version.
