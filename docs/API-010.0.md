# API-010.0 — Report Accuracy, Evidence and Coverage Validation

## Goal

Provide a consistent, opt-in quality gate for Cisco ASA, FortiOS, Snort and
Suricata reports, without inventing additional security findings or changing
existing response contracts. This milestone prioritizes detecting contradictory
analysis output and disclosing what the scanner has **not** proven.

## New endpoint

`POST /api/v1/analyze/validated`

Multipart field: `file` (the same upload validation as `/api/v1/analyze/universal`).
Optional query `platform`: `cisco_asa`, `fortios`, `snort`, or `suricata`.
Automatic platform detection is available where vendor-specific markers exist.

The response is **exactly** `/api/v1/analyze/assessment` plus one top-level
`quality` member. The legacy `/api/v1/analyze`, `/universal`, `/normalized`,
`/assessment` and `/ids-bundle` endpoints are not modified.

## Quality checks (all four platforms)

- Normalized finding count vs normalized findings.
- Adapter finding count vs adapter findings.
- Raw and normalized finding length, code, severity and **reported** line number.
- Unique finding IDs; valid severity categories.
- Exactly six severity totals matching normalized findings.
- Declared assessment coverage status and duplicate domains.
- Review-score weighted deductions and the 80/100 incomplete-coverage cap.
- Provisional and non-cross-platform-comparable score labeling.
- Inventory observation values compared to the adapter's structured report.
- Cisco ASA: preserve legacy summary/score meaning; do not infer missing routes
  from absent serializer fields.
- FortiOS: check policies, addresses, services and interfaces against inventory counts.
- Snort: check enabled/disabled rule counts and avoid claiming includes were loaded.
- Suricata: check enabled/disabled rule counts, and ensure rule-file references
  remain unassessed.

**IMPORTANT:** Quality diagnostics are **not** security findings. They are
not included in risk/severity totals or provisional score deductions. A `0`
quality-error count means the returned report is internally consistent within
implemented checks; it does **not** validate real-world device protection.
The quality layer does **not independently reread original source lines**:
`evidence.source_text_at_line_verified` is always `false`.

## Quality example (abbreviated)

```json
{
  "quality": {
    "version": "1.0",
    "platform_id": "suricata",
    "status": "limited_coverage",
    "structural_checks_passed": true,
    "summary": {
      "errors": 0,
      "review_items": 0,
      "observation_values_checked": 5,
      "issues_suppressed": 0
    },
    "finding_evidence": {
      "findings_crosschecked_with_adapter": 0,
      "findings_total": 0,
      "findings_with_reported_line_references": 0,
      "source_text_at_line_verified": false
    }
  }
}
```

The real response includes all existing report data, plus quality coverage,
issue details, interpretation, and a platform-specific limitation notice.

## Security model

Existing upload limits and decoding protections are unchanged and reused.
Configuration is untrusted inert text: no `eval`, shell commands, subprocess,
filesystem traversal, included rule expansion, external URL requests, or YAML
execution is added. The normalized report is produced via registered adapters.
Sensitive raw configuration lines and secrets are never copied into quality
messages. The file upload is processed exactly once.

## Dashboard integration

The optional frontend installer switches the unified upload's analysis endpoint
from `/assessment` to `/validated`, adds an optional `quality` type to the
normalized report, and inserts a small "Report accuracy checks" panel below
the unified upload results. All Cisco-specific detail pages, PDF-only controls,
professional PDF exporter, theme switcher and existing charts remain unchanged.
The new panel does not export separate JSON or create new security findings.

The existing PDF generator continues consuming the unchanged normalized
findings and severity fields. The quality panel is currently **dashboard-only**;
the quality section is not automatically added to the exported PDF. Report
crosschecks help detect data mismatches before an analyst relies on the PDF,
but they do not authenticate a downloaded PDF against live devices.

## Rollback

Restore `app/api/main.py.before_api0100.bak` to `app/api/main.py` to unmount
only the new endpoint. Restore `.before_api0100.bak` backups of
`frontend/src/api/universal.ts` and `frontend/src/pages/UniversalAnalysis.tsx`
if needed. The new `report_quality.py`, `validated.py`, and component files may
remain on disk unused. Rebuild the frontend after restoring files.
