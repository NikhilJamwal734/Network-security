## Scope

This is an **opt-in, allowlisted FortiOS CLI export subset**, not a full FortiGate policy auditor.
The FortiOS adapter (`platform_id=fortios`, `family=firewall`) recognizes top-level:

- `config firewall policy` — `edit`, `set action`, `set status`, `set srcaddr`, `set dstaddr`, `set service`, `set srcintf`, `set dstintf`, `set logtraffic`, `set utm-status`
- `config firewall address` — named address objects and explicit `set subnet`
- `config firewall service custom` — service object inventory
- `config system interface` — explicit `set allowaccess` protocols

Conservative checks `FORTIOS-001`–`FORTIOS-010` highlight visible broad selectors, explicit log disabling, disabled policies, broad interfaces, explicit UTM disablement, plaintext management protocols, explicit 0.0.0.0/0 address objects, absent policy sections in this *upload*, and malformed/unclosed blocks.

**Not assessed:** VDOM context, address/service groups, expanding names, policy order, implicit defaults, full policy semantics, NAT, VPNs, dynamic objects, device version, admin exposure, actual packet/traffic behavior. All detected issues are based on uploaded text, not a deployed device. No numeric FortiOS score is generated.

## Security

- Uploads are untrusted text: no execution, no filesystem-path resolution, no shell/CLI/device invocation.
- Uses the existing `read_untrusted_config()` on `.conf`, `.cfg`, `.txt`, preserving size, line, encoding, control-char and extension validation.
- Only allowlisted nonsecret `set` values are stored; reported output exposes select policy fields and inventory names, never passwords.
- The parser tolerates unknown commands without interpreting them, reports limited malformed lines, and caps nested block depth and warning storage.
- No additional Python dependencies.

## Endpoints

The **existing endpoints** automatically support FortiOS without `main.py` changes:

- `GET /api/v1/platforms` — lists `cisco_asa`, `fortios`, `snort`, `suricata` (sorted)
- `POST /api/v1/analyze/universal` — FortiOS raw static report and `platform_detection`
- `POST /api/v1/analyze/normalized` — API-009.3 schema, score `null`, FortiOS coverage

The older `POST /api/v1/analyze` remains strictly Cisco ASA only.

Launch server:

```powershell
.\.venv-win\Scripts\python.exe -m uvicorn app.api.main:app --reload --host 127.0.0.1 --port 8000
```

Second PowerShell terminal:

```powershell
curl.exe http://127.0.0.1:8000/api/v1/platforms
curl.exe -X POST -F "file=@configs/fortios_sample.conf" "http://127.0.0.1:8000/api/v1/analyze/universal"
curl.exe -X POST -F "file=@configs/fortios_sample.conf" "http://127.0.0.1:8000/api/v1/analyze/normalized?platform=fortios"
```

Strict detection: a standalone `set action accept` is not enough to identify FortiOS, and mixed ASA/IDS/FortiOS strong markers are rejected. Explicit `platform=fortios` requires a recognizable FortiOS section and rejects conflicting vendor syntax.
