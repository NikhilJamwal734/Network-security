# API-010.1 — Vendor-Specific Review + Green Sidebar

## Goal

Keep all existing Cisco ASA, FortiOS, Snort and Suricata normalized findings and scores, and **add a bounded, opt-in vendor review** for concrete text-visible settings. The separate `vendor_review` section records source references and limitations. It deliberately does not modify the original severity counts, findings, `assessment.review_score` or score deductions.

The frontend uses `POST /api/v1/analyze/deep-review`; it retains everything returned from API-010.0 `/validated` and additionally returns `vendor_review`.

## New vendor checks

| Code | Vendor | Specific condition | Limitation |
|---|---|---|---|
| ASA-DEEP-001 | ASA | Explicit `telnet 0.0.0.0 0.0.0.0 <interface>` | Real reachability is not assessed |
| ASA-DEEP-002 | ASA | Explicit all-IPv4 SSH management selector | ACLs/routing and management exposure unverified |
| ASA-DEEP-003 | ASA | Explicit `no logging enable` | Other logging paths may exist |
| FORTIOS-DEEP-001 | FortiOS | Enabled accept policy, `srcaddr all`, `dstaddr all`, service not `ALL` | Does not expand groups or resolve policy order |
| FORTIOS-DEEP-002 | FortiOS | WAN-*role* interface explicitly permits `https`/`ssh` | WAN role does not prove internet exposure |
| FORTIOS-DEEP-003 | FortiOS | Custom service `tcp-portrange` or `udp-portrange` spans almost all ports | Object might not be referenced by any policy |
| SNORT-DEEP-001 | Snort 2 | Enabled drop/reject/sdrop rule has any-to-any header, no commonly recognized constraints | Only known subset; deployment mode unknown |
| SNORT-DEEP-002 | Snort 2 | `HOME_NET` is `0.0.0.0/0` or equivalent literal | Includes/macro expansion not resolved |
| SURICATA-DEEP-001 | Suricata | Enabled drop/reject rule any-to-any without commonly recognized constraints | Runtime IPS mode unknown |
| SURICATA-DEEP-002 | Suricata | Supported YAML HOME_NET leaf uses `0.0.0.0/0` or equivalent | No general YAML resolution |

Existing broader severity findings remain as they were, without adding duplicate or new severity scores. Malformed or disabled rules are not considered enabled; pure YAML comments are not treated as detection rules.

## New API example

`POST /api/v1/analyze/deep-review?platform=snort`

Same multipart `file` upload as `/validated` (same security boundary and routing). The response is the original normalized report + `assessment` + `quality` +:

```json
{
  "vendor_review": {
    "version": "1.0",
    "platform_id": "snort",
    "scope": "supplemental_vendor_specific_static_review",
    "checks": [{
      "code": "SNORT-DEEP-001",
      "severity": "MEDIUM",
      "title": "Unrestricted inline blocking rule header",
      "detail": "...",
      "recommendation": "...",
      "line_number": 1,
      "rule_id": 1001
    }],
    "suppressed_checks": 0,
    "limitations": ["..."],
    "interpretation": "..."
  }
}
```

Checks cap at 40 per upload; reports show how many extras were suppressed. The engine never copies the complete source lines or any raw secret into this supplemental section.

## Frontend

- A **Vendor-specific configuration review** panel appears adjacent to the API-010.0 Report Accuracy panel.
- Each item shows severity as a **review priority**, source line, code, evidence and recommendation. Its total is **not** included in normalized finding counts.
- The unified formal PDF adds a **Vendor-specific supplemental review** section before assessment coverage.
- The entire left navigation pane uses a dark emerald background (`#064e3b`) while the current page uses brighter green (`#059669`). Main dashboard colors, severity badges, charts and PDF colors are unchanged.
- The CSS handles mobile navigation and light/midnight/cyber theme selectors.

## Scope honesty

This is **additional evidence-backed static triage** and a theme fix. It is not a complete FortiOS group/VDOM expansion engine, ASA effective policy simulator, Snort 3 parser, Suricata full YAML parser, or live IDS/IPS test. Those require more work and a real golden corpus to validate false-positive/negative behavior across device versions.
