# API-010.2 — Context-aware vendor precision review

## Objective

Improve **false-positive control and additional evidence checks** in the supplemental vendor-review section for Cisco ASA, Fortinet FortiOS, Snort 2-style rules, and Suricata. Changes deliberately **do not** change the main findings, security score, risk level, normalized schema, score deductions, or coverage model.

The current API-010.1 `/api/v1/analyze/deep-review` and API-010.0 `/validated` remain available and produce their previous content. API-010.2 adds a **new opt-in endpoint**:

`POST /api/v1/analyze/precision-review?platform=<cisco_asa|fortios|snort|suricata>`

Multipart field `file` (same upload validation and routing as before). The React dashboard switches to the new endpoint, retaining the same vendor-review component. The **sidebar, layout, theme, and PDF formatting do not change**; only a small precision summary and the refined findings displayed under Vendor-specific configuration review are new.

## Concrete additional accuracy checks

| Platform | Code | Behavior / evidence | Limitation |
|---|---|---|---|
| Cisco ASA | ASA-DEEP-001 / -002 | Reconcile exact enabled IPv4 `ssh` / `telnet` wildcard management selectors against subsequent identical `no ssh` / `no telnet` lines; report only final active selector and original line | Doesn't prove remote reachability, ACL, routing, or context effects |
| Cisco ASA | ASA-DEEP-003 | Only flag `no logging enable` when it is the final visible global logging enablement state; don't flag if later `logging enable` overrides it | No other logging path or operational log export evaluated |
| FortiOS | Existing FORTIOS-DEEP codes | With repeated edit identifiers, suppress affected observations when partial updates make effective values uncertain | Incomplete multi-edit merge, VDOMs, policy order and defaults remain unassessed |
| FortiOS | FORTIOS-PREC-001 | Explicitly disabled traffic logging on enabled accept policy | Logging may be intentionally disabled, other telemetry unknown |
| FortiOS | FORTIOS-PREC-002 | Explicit role `wan` + HTTP/Telnet management access on enabled interface | Interface role does not prove Internet reachability |
| Snort 2 | SNORT-PREC-001 | Duplicate SID across **enabled parsed** rules in uploaded file | Generator IDs, includes and Snort 3 Lua not resolved |
| Suricata | SURICATA-PREC-001 | Duplicate GID/SID combination across **enabled parsed** rules | External files, YAML aliases and runtime semantics not assessed |

Comments and disabled rules do not trigger duplicate-ID checks; unrecognized/unsupported source text is not interpreted as a security finding. All checks have a maximum of 40 results; extra results are counted as suppressed. No user-provided scripts or config commands are executed.

## Response differences

The existing `vendor_review` structure is preserved, with an optional `precision` object added **only on the new endpoint**:

```json
{
  "vendor_review": {
    "version": "1.0",
    "checks": [],
    "precision": {
      "version": "1.0",
      "status": "context_refined",
      "suppressed_preliminary_checks": 1,
      "additional_evidence_checks": 0,
      "note": "..."
    }
  }
}
```

The unchanged `assessment` and `quality` fields accompany the normalized findings, just as they do in the earlier deep-review endpoint. Original results are *not silently revised* for clients continuing to use API-010.1.

## Rollback

Stop the API and frontend. For each existing `.before_api0102.bak` file, copy it over the corresponding live file. Typically these are:

- `app/api/universal.py`
- `app/api/main.py`
- `frontend/src/api/universal.ts`
- `frontend/src/components/VendorDeepReviewPanel.tsx`
- `frontend/src/utils/normalizedPdf.ts`

Remove the newly added backend modules `app/core/precision_review.py` and `app/api/precision_review.py` **after** reverting route registration. Restart the API and rebuild the frontend.

No sidebar or theme file is ever modified by API-010.2.
