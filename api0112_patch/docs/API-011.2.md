# API-011.2 — Report Validation and Reporting Reliability

11.2 adds conservative contract preflight to the existing single-upload review
chain, after correlation accuracy. It validates report structure and internal
counts, not the accuracy of security findings and not the rendered PDF bytes.

Supported platforms: Cisco ASA, FortiOS, Snort, Suricata. Checks: platform IDs,
findings shape and declared totals, available review identities/statuses,
declared evidence counts where supported, consolidation sections/link totals,
correlation classification accounting, upstream link-count alignment, missing
PDF evidence arrays, and explicit omitted/limited coverage. Caps bound work and
output. It never removes or rescales prior findings.

`inconsistent`: a structural or count discrepancy exists.
`limited`: no contradiction observed but missing/partial evidence prevents clean review.
`consistent_subset`: checked contract assertions agreed; not a security signoff.

A separate browser PDF export integration is appended to `normalizedPdf.ts`.
For an end-to-end fidelity guarantee, run browser production build, generate
sample PDFs, inspect pages/fonts, and verify downloads and reproducibility.
The backend stage alone cannot establish that visual acceptance test.
