# API-010.5 — Network Object Resolution and Policy Selector Review

## Purpose

An opt-in, additive rule-selector interpretation layer for the existing FastAPI
configuration analyzer. The existing API-010.4 response is returned unchanged,
with an additional `object_resolution` property. The endpoint is:

`POST /api/v1/analyze/object-resolution`

The existing analysis validation and upload parser run once. A bounded copy of
uploaded bytes is captured *before* the previous endpoint processes and closes
the upload, preventing the prior API-010.3 closed-file regression.

### Source-specific supported syntax

Cisco ASA:

```
object network TRUSTED
 host 10.0.0.5
object network LAN
 subnet 10.1.0.0 255.255.255.0
access-list OUT line 10 extended permit tcp any any eq 443
access-list OUT line 20 extended deny tcp object TRUSTED any eq 443
```

- Simple `object network` IPv4 `host` / `subnet`, precisely one definition.
- Extended ACEs with literal `any`/`host`/`address netmask` or named `object`.
- Supported protocols: IP, ICMP, TCP, UDP. Numeric `eq` and `range` ports.
- Named groups, service aliases, ranges, FQDNs, `inactive`, NAT, routing,
  interface bindings and other extensions are *not* expanded or inferred.
- Two ACEs must belong to the same named ACL, and one must reference a
  resolved named object. No pair implies confirmed effective ACL shadowing.
- Explicit ACL sequence is reported if both ACEs provide comparable line labels.

Fortinet FortiOS:

```
config firewall address
 edit "LAN"
  set subnet 10.0.0.0 255.255.255.0
 next
end
config firewall service custom
 edit "TCP443"
  set tcp-portrange 443
 next
end
```

- Explicit IPv4 `firewall address` subnet objects; non-exclusion `addrgrp`
  members (bounded recursive expansion and cycle detection).
- One simple TCP-only `firewall service custom` destination port or range.
- Policies need explicit src/dst interfaces, src/dst addresses, service,
  schedule, accept/deny action and enabled status.
- Only policies with the **same explicit interface and schedule selectors**
  are compared. Effective policy priority is *not* verified.
- Built-in service names (e.g. HTTP), custom source-port constraints, service
  groups, VDOM blocks, VIPs, policies with inverted address filters, dynamic
  addresses, NAT and object mutations are not expanded. Missing definitions
  result in abstention, never fabricated membership.

Snort and Suricata: runtime variables and include files are **not assessed**
by this object-resolution layer. The older IDS header correlation continues
to operate independently, with its original limitations.

## Response schema

The extra `object_resolution` property contains:

- `status`: `reviewed_subset`, `limited`, or `not_assessed`.
- `summary`: definition counts, resolved rule counts, candidate pairs and caps.
- `objects`: bounded object inventory (resolved/unresolved, line, method).
- `pairs`: `OR-001` references with matched rule source lines, kind,
  resolution status, referenced objects and remediation-review advice.
- `limitations`: known model exclusions, explicitly distinguished from checks
  that completed.

`object_resolution` does **not** change `findings`, severity counts, previous
`rule_correlation`, `correlation_assurance`, provisional scores or legacy data.
No automatic remediation, network lookup or configuration execution occurs.

## Algorithm / confidence

Supported IPv4 networks are converted to Python `ipaddress.IPv4Network` using
valid contiguous masks. Named FortiOS groups are expanded recursively with a
cycle limit, and merged via `collapse_addresses` for set comparisons. Supported
TCP port intervals use closed, bounded numeric ranges. Pairwise comparisons
look for containment or intersection under those narrow semantics.

Every pair remains `resolved_selectors_conditional`, not "confirmed conflict".
External/device policy behavior is not simulated. Configuration-order claims
must be checked against the deployed device's effective policy and binding.

## Limits and false-positive discipline

- 2 MiB source text cap taken before the earlier endpoint closes the upload.
- 50,000-line cap; max 350 definition entries, 120 candidate rules, 60 pairs;
  response inventory shows up to 70 entries.
- Duplicate ASA object definitions and duplicate FortiOS named definitions
  abstain rather than applying unknown device edit semantics.
- Unknown service names are never converted to open ports.
- Unparseable or incomplete data does not become a negative finding or a
  positive certification of configuration security.
