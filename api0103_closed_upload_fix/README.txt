API-010.3: FIX FOR HTTP 500 - ValueError: I/O operation on closed file
========================================================================
Problem:
  POST /api/v1/analyze/rule-correlation first calls the API-010.2
  precision analyzer, which invokes analyze_universal. That earlier
  analyzer closes the uploaded file in a finally block. API-010.3 then
  attempts file.seek(0) on the closed upload and fails with HTTP 500.

Fix:
  The endpoint now reads a bounded 2 MiB + 1 byte correlation sample
  BEFORE handing the same upload to the existing precision analyzer.
  It rewinds the upload so the earlier security and platform validation
  still sees the complete file. The precision analyzer can close the
  upload normally; API-010.3 then correlates using the cached sample.
  No other endpoints, security checks, report formats or frontend CSS change.

Install from your actual project root in PowerShell:

  cd "C:\IoT\Information security\project 2\config analyzer"

  Expand-Archive -LiteralPath "$env:USERPROFILE\Downloads\API-010.3-Upload-500-Fix.zip" -DestinationPath "." -Force

  .\.venv-win\Scripts\python.exe .\api0103_closed_upload_fix\scripts\fix_closed_upload.py "."

Verify patch tests:

  .\.venv-win\Scripts\python.exe -m pytest -q .\api0103_closed_upload_fix\tests\test_closed_upload_fix.py

Verify existing tests:

  .\.venv-win\Scripts\python.exe -m pytest -q .\tests\test_api_010_3_correlation.py

Restart FastAPI (Ctrl+C in backend terminal) and launch:

  .\.venv-win\Scripts\python.exe -m uvicorn app.api.main:app --reload --host 127.0.0.1 --port 8000

Open http://localhost:5173 and upload the same configuration again.

Backup generated by installer (if the original file existed):
  app\api\rule_correlation.py.before_closed_upload_fix.bak

Manual rollback:
  Copy the backup over app\api\rule_correlation.py and restart backend.
