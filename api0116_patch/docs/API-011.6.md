# API-011.6 — Security Hardening and Input Validation

## Scope and operation

This additive release uses the new endpoint `POST /api/v1/analyze/hardened` as the React application's upload target. It validates one UTF-8 text configuration before delegating the **same bytes** to the existing API-011.4 pipeline. A successful response includes all previous report data plus `input_security_review`.

It accepts supported normalized platforms (`cisco_asa`, `fortios`, `snort`, `suricata`) or no explicit platform. Validation enforces a maximum of 8 MiB, UTF-8 with optional UTF-8 BOM, printable text (tabs and line breaks permitted), a maximum of 250,000 lines and 32,768 characters per line. It rejects empty/whitespace-only content, recognized binary/container formats, path-containing names and unsupported explicit platform names. It preserves the file pointer for prior analysis and does not echo the uploaded file in errors. SHA-256 in the report fingerprints the raw input for traceability, not malware detection.

The dashboard is **not modified**. The PDF receives an "Upload input validation — Detailed evidence" section, with the accepted upload's length, line count, SHA-256, checks and limitations. The Findings pane and all existing review/assessment sections remain unchanged.

## Important limits

1. Existing older endpoints remain accessible: **they are not protected** by this stage. Limit access to the intended entry point in deployment if appropriate.
2. The FastAPI/Starlette multipart parser consumes the request **before** this handler runs; ASGI and reverse-proxy limits are still required. The 8 MiB handler limit is not an upper bound on total inbound network bytes or multipart parser resource use.
3. These checks do not enforce a parser CPU/memory budget, guarantee secure YAML/Lua parsing, or prevent denial of service at the application layer. Use isolation, authentication/authorization when deployed beyond localhost, rate limiting, monitoring and system quotas as additional deployment controls.
4. Validated UTF-8 is not proof that the configuration is benign or the security review is accurate.
5. The `input_security_review` is included only after upstream analysis succeeds. Rejected uploads receive a 4xx error and produce no report or PDF.
6. An 8 MiB/line-count limit may reject legitimate larger configurations; do not automatically split a file if split semantics affect analysis. Revisit limits in API-011.5 or a later performance pass.

- Unit and multipart API tests exercise acceptance, rejection, upstream forwarding, and error propagation.
- Installer tests exercise Windows line endings, UTF-8 BOM, all-or-nothing validation, rerun, rollback, and refusal to overwrite customized source files.
- Run the normal full backend regression suite and React `npm run build` on the target machine.
