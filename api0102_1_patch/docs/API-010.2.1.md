# API-010.2.1 — Precision Accuracy Enhancements

## Intent

Improve the **opt-in** vendor-specific precision review introduced in API-010.2 while retaining existing security scores, normalized findings, API endpoints, dashboard and professional PDF styling. These findings appear as *supplemental vendor observations* and do **not** modify existing security-score mathematics.

## Security and evidence improvements

| Platform | Code | When triggered | Conservative interpretation |
|---|---|---|---|
| Cisco ASA | `ASA-PREC2-001` | Last visible explicit `ssh version` selects `1` | Explicit legacy protocol selection; effective SSH implementation not established |
| Cisco ASA | `ASA-PREC2-002` | Active `http 0.0.0.0 0.0.0.0 <interface>` selector **and** last `http server enable` is enabled | Broad ASDM/HTTPS management source selection; **not** proof of plaintext HTTP or Internet exposure |
| FortiOS | `FORTIOS-PREC2-001` | Accept policy explicitly declares `utm-status disable` and isn't explicitly disabled | Advisory: no UTM profiles on that policy; other security controls remain unknown |
| Snort 2-style | `SNORT-PREC-001` | Two or more enabled parsed rules share the same **GID/SID** pair | Different GIDs with the same SID are **not duplicates**. Invalid GID is excluded rather than guessed. |
| Suricata | `SURICATA-PREC-001` | Two or more enabled parsed rules share the same GID/SID | Both earliest and subsequent source-line references included |

### Sample source evidence

```text
alert tcp any any -> any any (gid:2; sid:101;)
alert udp any any -> any any (gid:2; sid:101;)
```

One supplemental finding carries `rule_id: "2:101"`, `line_number: 2`, and mentions `source lines: 1, 2` in the detail.

By contrast, `gid:1; sid:101` and `gid:2; sid:101` produce **no duplicate check**.

## Response contract

Existing `vendor_review.precision` fields remain in place, and now additionally include:

```json
{
  "enhanced_version": "1.1",
  "source_line_references": 3
}
```

Only illustrative counts shown. The existing React vendor-review panel displays observations and the expanded precision note. The professional PDF already prints the supplemental review checks and their evidence. No frontend files are changed.

### Operational boundaries

- Uploaded configuration is not executed.
- No file includes, external IDS rules, vendor defaults, interface state, real firewall reachability, or deployed IPS mode are resolved.
- FortiOS repeated `edit` identifiers are conservatively excluded from the UTM observation where partial edits make the effective value uncertain.
- A missing explicit field cannot be interpreted as proof that a control is enabled or disabled.
- Maximum 40 supplemental checks are shown; additional checks contribute to suppressed count.
- No modification of normalized security findings, score, coverage or any previous endpoint.
