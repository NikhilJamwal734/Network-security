# API-010.3 — Rule Correlation and Conflict Review

## Goal

Add **advisory**, evidence-cited rule correlation without changing existing
security findings, provisional scores, or API-010.2 responses. The new route is:

`POST /api/v1/analyze/rule-correlation?platform=<platform_id>` (multipart `file` upload).

The server first executes the existing API-010.2 precision-review request,
then adds `rule_correlation` to its result. Earlier routes remain unchanged.
The frontend switches to this endpoint and renders the same normalized report,
plus the new panel and PDF appendix.

## Supported comparisons

| Platform | Analysis | Explicit limits |
|---|---|---|
| Cisco ASA | Compare supported IPv4 `access-list NAME extended permit/deny` ACEs within **the same ACL**, using `any`, `host`, address/netmask, IPv4 TCP/UDP/ICMP/IP and numeric `eq`/`range` ports. Categorize conditional redundancy, shadowing, and intersecting opposite-action scopes. | Do not treat file order as proven device order; ignore unsupported address objects, ACL bindings, interface paths, time ranges, NAT, `inactive`, mixed explicit line ordering and runtime semantics. |
| FortiOS | Compare unique enabled `config firewall policy` entries with explicit action and identical source/destination interface, source/destination address, service and schedule selector names. | Does not resolve object membership, VDOM, edit order, policy movement or default values. Repeated policy edits and disabled policies excluded. |
| Snort | Compare enabled, parsed rule headers with distinct SIDs for matching traffic header fields; distinguish action interaction candidates. | Does not compare rule option semantics, flowbits, content, include paths, preprocessors or Snort 3 Lua. Equal headers **do not** imply equivalent rules. |
| Suricata | Same strict enabled rule-header comparison; YAML comment rules excluded. | Does not load referenced `rule-files`, process engine order, vars, options or live IPS mode. |

The `rule_correlation` object does not increment `summary.total_findings`, alter
`summary.severity_counts`, or change the original security or provisional scores.

## Bounded execution

- Max 2 MiB input for the secondary correlation pass, after original validated analysis.
- Max 50,000 source lines and 250 parsed rule candidates.
- Max 70 correlated pairs in response; PDF displays up to 40.
- Unknown, malformed or unsupported expressions are **not inferred**.
- Source line numbers are original 1-based line numbers for the uploaded file.
- No disk traversal, URL fetches, device commands, dynamic evaluation or rule execution.

## Important reporting interpretation

All classifications are **candidates**, not determinations of actual traffic
reachability or engine action precedence. A zero-pair result means only that the
supported review did not detect a candidate. It is not proof of security.
