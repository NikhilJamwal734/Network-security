# API-011.4 — End-to-End Pipeline Contract Checks

## Scope

Introduces `POST /api/v1/analyze/pipeline-validation` using the same upload shape
and optional `platform` query parameter as API-011.3. The endpoint delegates to
`analyze_pdf_readiness`, which already calls the earlier single-upload chain,
then adds `pipeline_validation_review`. It does not read the upload twice.

This is **report-side contract validation**, not a claim that browser download,
page rendering or independent artifact inspection has happened. The included
local smoke test exercises HTTP upload and the response chain against the actual
running service. A browser PDF download and saved-file audit are required to
complete the manual E2E verification.

## Checks

- Upstream successfully returned a normalized mapping after handling upload
- Known normalized platform identity
- Findings list shape (bounded inspection)
- Finding count consistency
- Existence, platform agreement, shape and declared status of the 11.0–11.3 reviews
- Explicit manual export verification requirement

The engine does not mutate existing findings, existing review metadata or score.
Review status can be `server_checks_passed`, `limited`, or `blocked`.
`server_checks_passed` does not mean PDF export was executed.

## UI / PDF

Dashboard includes at most two short labels; all explanatory stage evidence,
limitations and recommended actions are printed in the PDF. The 11.3 browser
PDF byte checker remains in place.

## Limitations and security

- Do not use the stage as an independent security vulnerability verification.
- The smoke test limits uploads to 8 MB, responses to 10 MB and URLs to localhost.
- Test only with authorized configuration samples (configs may contain secrets).
- Cover all four platforms with representative samples before releasing.
- Run the full test suite and `npm run build` on the actual Windows checkout.
- Verify a saved PDF structurally and visually; backend can't prove it downloaded.
