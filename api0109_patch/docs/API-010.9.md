# API-010.9 — Snort and Suricata static IDS configuration review

## Integration

Adds `POST /api/v1/analyze/ids-configuration` (multipart `file`, optional `platform`) on top of the existing API-010.8 upload endpoint. It adds `ids_deep_review` and preserves the complete preceding normalized report, earlier findings and severity score. Up to 2 MiB of the upload is snapshotted and rewound *before* invoking the prior endpoint, which might close the uploaded file. The frontend's upload endpoint changes to API-010.9. No sidebar/theme or previous dashboard cards change.

## Dashboard vs PDF

**Dashboard:** one compact panel for Snort/Suricata, only counts and maximum two `IDS-*` kind-label snippets. It does not display source excerpts, long descriptions, interpretation or remediation. ASA/FortiOS have no IDS panel.

**PDF:** full bounded evidence per item: source line, setting, confidence, observation, impact interpretation, remediation guidance and coverage limits. No changes to the previous report sections.

## Scoped checks and limitations

| Platform | Static, bounded observations | Cannot conclude |
|---|---|---|
| Snort 2 conf / selected Snort 3 Lua text | Explicit `HOME_NET any` declarations, `include` and `output` directives, single-line inline rules with numeric SID and repeated GID/SID pairs; Lua multiline comments skipped | Validity/evaluation of the full Lua AST, effective loaded signatures, included files, real alert plugin state, signature precedence, multiline rules, running IPS mode |
| Suricata YAML | Safe single-file parsing of selected `vars.address-groups.HOME_NET`, explicit output `enabled` flags, supported `af-packet` / `pcap` / `netmap` interface declarations, conditional missing `copy-iface` with `copy-mode: ips`, and `rule-files` references | Whether referenced rule files exist/are loaded, real output delivery, runtime interface availability, overridden start commands, effective packet processing, operational IPS/IDS detection |
| Cisco ASA / FortiOS | Existing complete normalized analysis and NAT/routing preserved | This IDS-specific reviewer returns `not_applicable` |

This is **configuration intent evidence**, not conclusive vulnerability validation. For example: `enabled: false` refers to one output entry, not total absence of alert logging, and an empty `rule-files` list is not proof that zero rules loaded.

The YAML reviewer uses PyYAML SafeLoader with explicit duplicate-key and alias rejection, avoiding silent last-wins behavior. Unparsable/duplicate/unsafe YAML returns `limited` with no fabricated setting findings. No custom tags are constructed or Lua executed. A missing PyYAML dependency also returns `limited` rather than misreporting a clean configuration.

## Defensive bounds

- Max upload snapshot: 2 MiB; max 40,000 lines; max line length 8,192 characters.
- Max 2,000 inspected inline rule lines; max 80 evidence items; overflow marked incomplete.
- Suricata capture/output list review capped to first 100 entries per block, with omissions surfaced.
- YAML nesting beyond 32 levels is rejected by the source location mapper.
- No network requests, device queries, filesystem include access, Lua/YAML runtime evaluation or automatic rule changes.
- No prior severity, counts, or score recalculated.

## Testing

`pytest` covers duplicated Snort GID/SID, comments, rule-file references, strict Suricata YAML, unsafe YAML abstention, explicit enabled/disabled controls, missing AF_PACKET pairing, line numbers, caps, upstream file closing, installation preflight, backup and idempotence. Build and test the real checkout separately after installation.
