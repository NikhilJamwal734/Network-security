# API-011.3 — PDF export readiness and integrity (PDF-first)

## Goal and architecture

11.2 checks the normalized report **before** PDF rendering. This stage adds:

- `POST /api/v1/analyze/pdf-readiness`, delegating to the 11.2 analyzer, appending a read-only `pdf_export_review` preflight with bounded, human-reviewable observations.
- A compact React dashboard review card showing counts and at most two observation **names**. Original findings remain in the Findings pane.
- A detailed preflight evidence section in the jsPDF report, explicitly distinguishing upstream data consistency from browser byte checks.
- Browser export verification: page count, `%PDF-` header, `%%EOF` trailer, bounded bytes, and using the **same validated bytes** in the download `Blob`.
- Optional saved-file audit with `pypdf` to independently parse pages, extract required section headings and compare page footers.

## Scope of results

The `pdf_export_review.status` values are `preflight_pass`, `limited`, and `blocked`. They describe **report-data readiness**, not whether the PDF itself was rendered correctly or delivered to disk.

The PDF browser checks are structural heuristics. They cannot detect clipped glyphs, truncated source text, font coverage issues, or the browser declining the download. For an audit-grade report, verify the saved PDF independently and visually inspect representative pages.

The PDF displays at most 300 findings and some review sections have narrower limits. A user should retain the normalized JSON where evidence is truncated. A *limited* report is not an all-clear.

## Retained behavior

- Supports the existing normalized platform IDs: Cisco ASA, FortiOS, Snort, and Suricata.
- No edits to source findings, scoring, ordering, prior validation reviews, or the separate Findings pane.
- PDF evidence from stages 10.x–11.2 remains before the Assessment Coverage section.
- Both API 11.3 patch installers validate source anchors; combined installer preflights both halves.
- Rollback checks SHA-256 fingerprints to avoid destroying subsequent user edits.

## Test strategy

1. Backend preflight: missing or malformed shapes, cap disclosure, invalid platform, input immutability.
2. Patch installer: correct structure, repeat installation, Windows UTF-8/CRLF preservation, reject changed layouts, safe rollback, refuse overwriting custom additions.
3. Frontend integrity helper: malformed byte structures rejected in a compiled TypeScript/Node smoke test.
4. Optional saved-file parser: independent parsing and required-section extraction.
5. The actual Windows frontend build and representative PDF downloads remain required before production use.
